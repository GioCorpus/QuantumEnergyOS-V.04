## 1. Executive Summary

P7.6 extends `qeos-cluster` with a resource-aware distributed scheduler, a
validated distributed job model, backend routing and a typed, authorized,
auditable remote-administration layer. No unrestricted remote shell is
introduced; every privileged operation is a typed command with identity,
authorization, request id, timeout and audit.

**Baseline (P7.5):** 699 tests. **After P7.6:** 722 tests (+23), clean compile,
clippy-clean, zero unsafe.

---

## 2. P7.6-00 — Scheduler Baseline

Jobs express CPU/RAM/GPU/VRAM/QPU/storage/network/energy/latency requirements.
Nodes publish availability snapshots. Verified in `resources.rs`.

---

## 3. P7.6-01 — Resource-Aware Scheduling

`crates/qeos-cluster/src/scheduler.rs`:
- Inputs: requirements, per-node availability snapshot, priority,
  affinity/locality hint, latency bound, energy-capacity check.
- `Scheduler::schedule` places a job on the first healthy node whose snapshot
  satisfies requirements; honors affinity and latency bounds; returns an
  observable `Placed(Placement)` or `Deferred(reason)`.
- QPU job → `qpu-sim` backend; GPU job → `gpu-sim`; otherwise `cpu`.
- **No claim of optimal scheduling** — deterministic, documented policy;
  optimality would require P7.9 benchmarks.

**REAL.** Tests: 7.

---

## 4. P7.6-02 — Distributed Job Model

`crates/qeos-cluster/src/job.rs` — `DistributedJob` with states
CREATED/QUEUED/ASSIGNED/RUNNING/COMPLETED/FAILED/CANCELLED/TIMEOUT/RETRYING,
fields job_id/node_id/backend/timestamps/result/error/telemetry, validated
transitions (terminal states are final; Failed → Retrying for reschedule).

**REAL.** Tests: 5.

---

## 5. P7.6-03 — Distributed Quantum Jobs

`Scheduler::pick_backend` routes QPU jobs to a `qpu-sim` (or future `vendor-qpu`)
backend. Retry (`Retrying`), timeout (`Timeout`), cancellation (`Cancelled`),
result retrieval and reproducibility (deterministic seed) are supported by the
job model. Real QPU backends remain `UNAVAILABLE` (see P7.4) and are never
implied.

---

## 6. P7.6-04 — Distributed GPU Jobs

GPU jobs (requiring `gpu>0`) are placed only on nodes whose snapshot reports
sufficient `gpu`/`vram`, and routed to the `gpu-sim` backend. GPU hardware is
`UNAVAILABLE` (see P7.3); placement/monitoring/failure logic is REAL.

---

## 7. P7.6-05/06 — Remote Administration & Command Security

`crates/qeos-cluster/src/admin.rs` — `RemoteAdmin`:
- Typed `AdminOperation` (GetStatus/GetHealth/RestartService/CancelJob/
  CollectDiagnostics/QuiesceNode) — **no shell access**.
- Every `AdminRequest` carries request_id, principal, permission, timeout.
- `PermissionAuthorizer` (View/Operate/Administer) enforces the minimum
  permission per operation.
- Every attempt (allowed or denied) is recorded in an `AuditLog` with
  request id, principal, operation, timestamp, outcome.

**REAL.** Tests: 6.
