## 1. Executive Summary

P7.8 adds a research platform (`crates/qeos-research`) — experiments, versioned
datasets, integrity-protected artifacts, reproducibility records and validated
workflows — and a working `qeos` CLI (`crates/qeos-cli`) backed by real crate
functionality. A complete reproducible experiment was validated end-to-end.

**Baseline (P7.7):** 741 tests. **After P7.8:** 762 tests (+21), clean compile,
clippy-clean, zero unsafe, working CLI.

---

## 2. P7.8-00/01 — Experiment Model & Lifecycle

`crates/qeos-research/src/experiment.rs` — `Experiment` captures id, timestamp,
user, software/runtime versions, backend/device, parameters/configuration,
seed, input/output, telemetry and artifact ids. Lifecycle states
CREATED/VALIDATED/QUEUED/RUNNING/MEASURING/COMPLETED/FAILED/CANCELLED/ARCHIVED
with validated transitions.

**REAL.** Tests: 4.

---

## 3. P7.8-02 — Dataset Infrastructure

`crates/qeos-research/src/dataset.rs` — `Dataset` (id, version, checksum,
schema, source, license, provenance) in a `DatasetRegistry`. **No silent
overwrite**: registering an existing id+version is rejected.

**REAL.** Tests: 4.

---

## 4. P7.8-03 — Artifact Infrastructure

`crates/qeos-research/src/artifact.rs` — `Artifact` (Model/Checkpoint/Dataset/
Result/Binary/Notebook/Log/Measurement) with version, checksum, owner, and
provenance. `ArtifactStore.add` verifies the checksum and rejects id collisions.

**REAL.** Tests: 4.

---

## 5. P7.8-04 — Reproducibility

`crates/qeos-research/src/reproducibility.rs` — `EnvironmentRecord` records
source commit, compiler, toolchain, dependencies, runtime, hardware, backend,
seed, parameters, configuration, dataset/model versions.
`verify_reproduction` returns `Reproducible` or `Diverged`.

**REAL.** Tests: 4.

---

## 6. P7.8-05 — Research Workflow

`crates/qeos-research/src/workflow.rs` — `Workflow` over Dataset→…→Artifact
stages with versioning, timeout, retry policy and checkpointing; `validate`
enforces a well-formed pipeline.

**REAL.** Tests: 4.

---

## 7. P7.8-06 — Research Workspace

Notebook/Python/JupyterLab integration is **only** wired when a runtime is
actually available; none is bundled in this phase (documented under limitations).
The CLI and Rust SDK provide the integration surface.

---

## 8. P7.8-07 — Developer SDK

Primary language Rust. The SDK surface is the public crates: `qeos-node`,
`qeos-gpu-compute`, `qeos-qpu`, `qeos-cluster`, `qeos-research` (plus
`identity-service`, `quantum-runtime`). Python/TypeScript are used only where
justified (none added this phase).

---

`crates/qeos-cli` → `qeos` executable. Real commands, each with `--help`,
structured JSON output and exit codes (0 success / 1 error / 2 usage):

| Command | Behavior | Evidence |
|---|---|---|
| `qeos doctor` | platform/backends self-checks | node+GPU+QPU checks true |
